False Positive in Nikto — SimpleHTTP/0.6 Flagged as Outdated

Open Source Contribution — Nikto Web Scanner

Open Source Nikto v2.6.1 False Positive Fixed 2026

What I Found

While running Nikto against a local copy of a website I was assessing, I noticed this warning:

[600720] SimpleHTTP/0.6 appears to be outdated (current is at least 1.2)

The target was Python's built-in HTTP server, which I was using only for local testing. The warning seemed wrong — I had just installed Python and knew it was recent. That made me question whether Nikto was actually detecting something real.

Why It's a False Positive

Nikto maintains a database called db_outdated that maps software names to their expected current versions. When the version in a Server header is lower than the one in the database, it fires a warning.

The relevant entry in that database is:

"600720","SimpleHTTP/","1.2"

Nikto reads SimpleHTTP/ from the Server header, finds 0.6 after it, compares against 1.2, and concludes the software is outdated.

The problem is that 0.6 is not a version number that changes when you update Python. It is a fixed label hardcoded directly into Python's source code:

# From cpython/Lib/http/server.py
__version__ = "0.6"
server_version = "SimpleHTTP/" + __version__

This value has been the same in every Python release since 2.1 (2001):

  • Python 2.1 through 2.7 send SimpleHTTP/0.6
  • Python 3.0 through 3.14 send SimpleHTTP/0.6
  • The older releases I could check used lower numbers: 0.3 in Python 1.5.2 and 0.5 in Python 2.0

No Python release I checked, from 1.5.2 to 3.14, sends SimpleHTTP/1.2. The 1.2 version in Nikto's database most likely belongs to a different product that happens to share the SimpleHTTP name — but regardless, it will never match Python's server.

The result is that this warning fires on every Python HTTP server in every Python release so far, and upgrading Python doesn't clear it. It is a false positive by definition. Python's development branch drops the number and sends just SimpleHTTP, so future releases probably won't match this entry at all.

What Is Still Valid

Not everything Nikto flagged here was wrong. Two things from the same scan are legitimate:

  1. Version disclosure. The Server header reveals exactly what software is running. That is a real finding regardless of whether the version comparison is accurate.
  2. Python version. The separate check [600652] flagging Python/3.13.9 as outdated is a fair question. Python 3.13 is still a supported release line, though, so the real question is whether 3.13.9 is the latest 3.13 patch, not whether 3.14 exists. That is a separate check from 600720 and is not part of this false positive.

The false positive is specifically the SimpleHTTP version comparison, not the broader version disclosure finding.

How I Reported It

After tracing the issue through both CPython's source code and Nikto's scanner database, I filed a bug report to the Nikto project on GitHub with:

  • The scan output showing the false positive
  • The specific db_outdated entry causing it
  • Source references to both CPython and Nikto's database
  • A question asking which product the 1.2 version is actually intended to match

The goal was not just to report the symptom but to give the maintainers enough information to either correct the database entry or add a more specific product name to avoid matching Python's server incorrectly.

Source references used in the report:

  • cpython/Lib/http/server.py (Python 3.13)
  • nikto/program/databases/db_outdated (entry 600720)

Resolution

Nikto's maintainer (@sullo, the repository owner) confirmed the bug the same day, labeled the issue as a bug, and closed it as completed:

"Interesting, thanks for pointing this out. I did some searching and can't find a product that matches with version 1.2 (though a similarly named client is version 1.2.0). I think this is just some noise in the DB. I've gone ahead and updated it in the pre-release branch for the next release (very soon)."

That also answered the question in my report: no product actually matched the 1.2 version. The entry was noise in the database.

The fix changes entry 600720 to compare against 0.6, the label Python's server actually sends:

- "600720","SimpleHTTP/","1.2",...
+ "600720","SimpleHTTP/","0.6",...

The change is on Nikto's pre-release branch and ships with the next release. Until then, the current release still shows the warning.

Takeaway

Running a scanner and copying its output is not a security assessment. Every finding needs to be validated against the actual target before being reported. In this case, questioning a result that seemed wrong led to identifying a bug in the tool itself — something that affects every security professional who runs Nikto against a Python server and trusts the output without verifying it.
